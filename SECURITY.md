# Security Policy

## Supported versions

Every project in this workspace is at `0.1.0-dev` (early development). Security fixes land on the default branch.

## Reporting a vulnerability

Report vulnerabilities through the GitHub private vulnerability reporting form:

https://github.com/unalivin/workspace/security/advisories/new

Do not open a public issue for a security vulnerability.

## What to include

- The project folder name and version
- Steps to reproduce or a minimal fixture
- The impact you observed and any suggested fix

## Response expectations

We aim to acknowledge reports within 5 business days and provide a status update within 14 days.

## Scope

In scope: vulnerabilities in any of the 25 tools, their parsers, storage layers, or build scripts.

Out of scope: third-party dependencies unless exploitable through our code, and issues requiring physical access to an unlocked machine.

## Disclosure

We coordinate disclosure through the GitHub advisory and credit reporters who want to be named.
